# CAGE Framework Dependencies
# Python 3.13 required (canonical: CAGE_CANONICAL_PYTHON in scripts/lib/_common.sh;
# Tier-1 exact pins below were frozen and tested on CPython 3.13.7, 2026-08-04 —
# any other interpreter makes them an untested claim; finding B1 2026-08-07)
#
# ============================== PINNING POLICY ===============================
# (CAGE_TECHNICAL_REVIEW_2026-08-04.md §5 S1/S17/S18; PUBLICATION.md D9 §9.13:
# "the registered SHA must be the runnable, calibrated one".) Four tiers:
#
#   Tier 1 — EXACT PIN (==): scientific instruments whose version is RESOLVED
#     AND TESTED in the local analysis venv (.venv, `pip freeze` 2026-08-04),
#     or whose PyPI-latest release equals the long-stable floor (verified via
#     `pip index versions` 2026-08-04). The pin records tested reality.
#   Tier 2 — TIGHT BOUNDED RANGE (>=floor,<cap): scientific instruments that
#     only fully resolve on the GPU host (co-resolved with vllm==0.19.1 and
#     the CUDA stack), where a laptop-minted exact pin would record an
#     UNTESTED claim or break platform wheel resolution (torch). Caps sit just
#     above the PyPI-latest verified 2026-08-04. Exact values get frozen into
#     requirements.lock.txt at D8 calibration time (review §4.8) — that
#     lockfile pass is a separate, still-open item.
#   Tier 3 — FLOOR PIN (>=): non-scientific infrastructure (serving,
#     orchestration, CLI, testing) where version drift cannot change a
#     reported number.
#   Tier 4 — GIT SHA: internal tools (cage-stats), pinned to an exact commit.
#
# A Tier-1 pin is only ever changed by a DELIBERATE bump + re-test, never by
# deleting the pin. Doctrine test: tests/test_scripts_doctrine.py fails on any
# scientific-instrument line that regresses to a bare floor pin.
# =============================================================================
